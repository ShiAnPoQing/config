# Modules

该包库为 Lua 中加载模块提供了基本功能。
它直接在全局环境中导出一个函数: `require`。

其他所有内容都导出在表 `package` 中 

## `require(modname)`

>加载指定的模块

1. 首先检查 `package.loaded` 表，确定 `modname` 是否已被加载。
2. 如果已加载，则 `require` 返回存储在 `package.loaded[modname]` 中的值。
3. 如果没有第二个结果，则表示此次调用无需加载该模块。
4. 否则，它会尝试查找该模块的加载器

`require` 会参考 `package.searchers` 表。
该表中的每个条目都是一个搜索函数，以特定的方式搜索模块。

通过更改此表，我们可以更改 `require` 查找模块的方式。

`package.searchers` 的默认配置

第一个 `searcher` 会查询 `package.preload[modname]`。
如果该值有值，则此值（必须是一个函数）即为加载器。
否则，`require` 会使用存储在 `package.path` 中的路径查找 lua 加载器
如果仍然找不到，则会使用存储在 `package.cpath` 中的路径查找 C 加载器。k
如果上述方法也失败，则会尝试使用一体化加载器

找到加载器后，`require` 会调用该加载器并传递两个参数：
`modname` 和一个额外的加载器数据，该数据也由搜索器返回
加载器数据可以是任何对模块有用的值；对于默认搜索器，它指示加载器的位置。
（例如，如果加载器来自某个文件，则此额外值是文件路径。）
如果加载器返回任何非空值，`require` 会将该返回值赋给 `package.loaded[modname]。`
如果加载器未返回非空值且未将任何值赋给 `package.loaded[modname]，则` `require` 会将该条目赋值为 `true`。
无论哪种情况，`require` 都会返回 `package.loaded[modname]` 的最终值。
除了该值之外，`require` 还会返回搜索器返回的加载器数据作为第二个结果，该数据指示 `require` 是如何找到该模块的。

如果加载或运行模块时出现任何错误，或者找不到模块的任何加载器，则 `require` 会引发错误。

~~~lua
--伪代码
package.searchers = {
    -- package.preload 
    function(modname, loader_data)
      return package.preload[modname], loader_data
    end,
    -- package.path 
    function(modname, loader_data)
        local path = package.searchpath(modname, package.path)
        local loader = loadfile(path)
        return loader, path
    end,
    -- package.cpath
    function(modname, loader_data)
        local path = package.searchpath(modname, package.cpath)
        local loader = loadfile(path)
        return loader, path
    end,
    -- all-in-one
    function(modname, loader_data)
    end
}


function require(modname) 
    if package.loaded[modname] ~= nil  then
        return package.loaded[modname]
    end

    for _, searcher in ipairs(package.searchers) do
        local loader, loader_data = searcher(modname)
        if loader ~= nil then
            local mod = loader(modname, loader_data)
            if mod ~= nil then
                package.loaded[mod] = mod
            else
                package.loaded[mod] = true
            end
            return package.loaded[mod], loader_data
        end
    end
    return error("找不到模块")
end
~~~

## `package.config`

描述软件包编译时配置的字符串

该字符串由以下几行组成：

1. 第一行是目录分隔符。Windows 默认为 `\`，其他系统默认为 `/`
2. 第二行是路径中模板中的分隔符。默认为`;`。
3. 第三行是模板中替换点的标记字符串。默认为 `?`。
4. 第四行是一个字符串，在 Windows 系统中，该字符串会被替换为可执行文件的目录。默认为 `!`。
5. 第五行是一个标记，用于构建 luaopen_ 函数名时忽略其后的所有文本。默认为 `-`。

## `package.cpath`

一个字符串，其中包含 `require` 函数用于查找 C 加载器的路径

Lua 初始化 C 路径 `package.cpath` 的方式与初始化 Lua 路径 `package.path` 的方式相同,
使用环境变量 `LUA_CPATH_5_5`、环境变量 `LUA_CPAT` 或 `luaconf.h` 中定义的默认路径。

## `package.loaded`

`require` 函数使用一个表来控制那些模块已被加载。
当你引入一个模块 `modname` 且 `package.loaded[modname]` 不为 `false` 时，
`require` 函数会直接返回存储在该表中的值

这个变量只是对实际表的引用；对该变量的赋值不会改变 `require` 函数使用的表。
实际的表存储在 C 注册表中，索引键为 `LUA_LOADED_TABLE`，该键是一个字符串

## `package.loadlib(libname, funcname)`

将宿主程序与 C 库 libname 动态连接。

如果 funcname 为 `*`，则仅链接该库，使库导出的符号可供其他动态链接库使用。
否则，它会在库中查找函数 funcname，并将其作为 C 函数返回。
因此，funcname 必须遵循 lua_CFunction 原型。

这是一个底层函数。它完全绕过了包和模块系统。
与 `require` 不同，它不执行任何路径搜索，也不会自动添加扩展名。
libname 必须是 C 库的完整文件名，必要时包含路径和扩展名。
funcname 必须是 C 库导出的确切名称

此功能不受 ISO C 的支持。因此，loadlib 仅在某些平台上可用：Linux、Windows、Mac OS X、Solaris、BSD 以及其他支持 dlfcn 标准的 Unix 系统。

这个函数本质上是不安全的，因为它允许 Lua 调用系统中任何可读动态库中的任何函数。（Lua 调用任何函数都假定该函数具有正确的函数原型并遵循正确的协议（参见 lua_CFunction）。因此，调用任意动态库中的任意函数通常会导致访问冲突。）

## `package.path`

一个字符串，其中包含 `require` 函数用于查找 lua 加载器的路径。

启动时， Lua 会使用环境变量 LUA_PATH_5_5 或 LUA_PATH 的值初始化此变量；

如果这些环境变量未定义，则使用 `luaconf.h` 中定义的默认路径。
环境变量值中的 `;;` 会被替换为默认路径

## `package.preload`

用于存储特定模块加载器的表

此变量仅是对实际表的引用；对此变量的赋值不会更改 require 使用的表。实际表存储在 C 注册表中（参见 §4.3），索引键为 LUA_PRELOAD_TABLE，该键为字符串类型。

## `package.searchers`

`require` 使用的表，用于控制如何查找模块。

此表中的每个条目都是一个搜索函数。

查找模块时，`require` 会按升序调用这些搜索函数，并将模块名称(传递给 `require` 的参数)作为其唯一参数。 

如果搜索函数找到模块，它会返回另一个函数（模块加载器），以及一个额外的值（加载器数据），
该值将传递给加载器，并作为 `require` 的第二个结果返回。
如果找不到模块，它会返回一个字符串来解释原因（如果没有其他信息，则返回 `nil`）

Lua 使用四个搜索函数初始化此表

第一个搜索函数直接在 `package.preload` 表中查找加载器。

第二个搜索函数使用 `package.path`  中存储的路径查找 Lua 库中的加载器。
搜索过程如函数 `package.searchpath` 中所述

第三个搜索函数使用 `package.cpath` 变量提供的路径查找 C 库中的加载器。
同样，搜索过程按照 `package.searchpath` 函数中的描述进行。

例如，如果 C 路径是字符串：

"./?.so;./?.dll;/usr/local/?/init.so"

则模块 foo 的搜索器会按顺序尝试打开文件 ./foo.so、./foo.dll 和 /usr/local/foo/init.so。找到 C 库后，搜索器首先使用动态链接机制将应用程序与该库链接起来。然后，它会尝试在该库中查找用作加载器的 C 函数。该 C 函数的名称是字符串“luaopen_”加上模块名称的副本，其中每个点号都被替换为下划线。此外，如果模块名称包含连字符，则会删除第一个连字符之后（包括第一个连字符本身）的后缀。例如，如果模块名称是 a.b.c-v2.1，则函数名称将是 luaopen_a_b_c。

第四个搜索器尝试使用一体化加载器。它会在 C 路径中搜索给定模块根名称的库。例如，当需要 a.b.c 时，它会搜索 a 的 C 库。如果找到，它会在其中查找子模块的 open 函数；在我们的示例中，该函数为 luaopen_a_b_c。借助此功能，一个包可以将多个 C 子模块打包到一个库中，每个子模块都保留其原始的 open 函数。

除第一个搜索器（preload）外，所有搜索器都会返回模块所在文件路径作为额外值，该路径由 package.searchpath 返回。第一个搜索器始终返回字符串“:preload:”。

搜索器在 Lua 中不应引发错误，也不应产生任何副作用。（它们在 C 中可能会产生副作用，例如将应用程序与库链接。）

## `package.searchpath(name, path[, sep[, rep]])`

路径是一个字符串，其中包含一系列以分号分隔的模板。
对于每个模板，该函数会将模板中的每个问号（如果有）替换为名称的副本，
其中所有出现的 sep（默认为点号）都被替换为 rep（默认为系统目录分隔符），然后尝试打开生成的文件名。

例如，如果路径是字符串：

"./?.lua;./?.lc;/usr/local/?/init.lua"

则搜索名称 foo.a 将按顺序尝试打开文件 ./foo/a.lua、./foo/a.lc 和 /usr/local/foo/a/init.lua。

返回第一个可以以读取模式打开的文件的名称（在关闭文件之后），如果没有任何文件成功打开，则返回失败并附带错误消息。
（此错误消息列出了它尝试打开的所有文件名。）
